# Customer Voice Release Intelligence

An automated mobile-app review intelligence pipeline for Google Play + Apple App Store. It incrementally ingests reviews, enriches only new records with NLP, detects statistically meaningful issue spikes, compares release health, surfaces recurring emerging complaints, and publishes a GitHub Pages dashboard plus daily reports.

## What changed in this version

- Persistent `data_master.json` with stable review IDs and deduplication.
- Incremental NLP: previously processed reviews are not re-run daily.
- One canonical taxonomy in `config/settings.json`.
- Multi-label issue classification with model confidence retained.
- 7-day baseline anomaly detection instead of "any negative review = alert".
- Issue severity score and release/version health scoring.
- Emerging-issue phrase mining from negative reviews.
- Optional OpenAI investigation agent; deterministic fallback means no API key is required.
- Unified GitHub Pages dashboard (`index.html`).
- Automated tests and pre-publish JSON validation.

## Deploy in GitHub

1. Upload the contents of this repo to your GitHub repository (replace the old files if this is an upgrade).
2. In **Settings → Pages**, deploy from your repository branch/root if Pages is not already enabled.
3. Open **Actions → Customer Voice daily intelligence → Run workflow** for the first run.
4. The scheduled workflow also runs every day at 11:00 UTC.

No secret is required for the core pipeline.

### Optional AI investigation agent

If you want the LLM investigation brief, create a GitHub Actions secret named `OPENAI_API_KEY`. You can optionally create a repository variable `OPENAI_MODEL`; otherwise the workflow uses `gpt-5`. If the key is absent or the API call fails, `agent_brief.json` is generated by the deterministic fallback and the pipeline continues.

## Key files

- `config/settings.json` — stores, NLP taxonomy, alert thresholds and history windows.
- `scripts/pipeline.py` — fetch, dedupe, incremental enrichment and dashboard window.
- `scripts/analytics.py` — anomaly detection, severity, release health, emerging issues.
- `scripts/agent_investigator.py` — optional evidence-grounded investigation brief.
- `analytics_summary.json` — structured analytics consumed by the dashboard.
- `agent_brief.json` — daily investigation output.
- `data_master.json` — retained review history.
- `data.json` — current 30-day dashboard window.

## Alert rule

By default an issue triggers when the latest review date has at least 3 negative reviews in the category **and** volume is at least 1.75× its prior 7-day daily average. Adjust these values in `config/settings.json`.

## Notes

The first run after upgrading bootstraps `data_master.json` from the existing `data.json`, preserving your current review history. Legacy rows may not have confidence scores or multi-label `issues` until they are naturally replaced by newer data; all newly ingested reviews use the new schema.

The emerging-issue detector is intentionally lightweight so the daily GitHub Action stays reliable. It mines repeated phrases from negative reviews instead of adding another large embedding model to every run. This can later be upgraded to embedding-based clustering if volume grows enough to justify it.
